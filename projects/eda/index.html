    Project 1 — EDA: Hotel Booking Demand

    Question. Can we tell, at booking time, whether a hotel booking will be canceled? Target: is_canceled (binary classification). This EDA ends with a preprocessing pipeline ready for the neural network of the next deliverable; no model is trained here.

    How to reproduce. Everything below comes from two files in code/:

    • code/pipeline.py — importable module: loading, row cleaning, the split and the Pipeline + ColumnTransformer (section 4.C);
    • code/eda.py — every figure in figures/, every number quoted (figures/results.json) and the long tables (figures/tables.txt, embedded below as snippets, so the tables in this page are the program output, not hand-copied).
    pip install -r requirements.txt
python docs/projects/eda/code/eda.py     # ~2 min; runs from a clean clone (the CSV is in data/)

    random_state = 42 everywhere (split, samples, t-SNE, UMAP). Two consecutive runs produce an identical results.json.

    0. Proposal

    Three datasets were checked against the requirements (public, tabular, ≥ 1 000 rows, ≥ 5 features with both numerical and categorical ones, target in the file, not a classic): Hotel Booking Demand (119 390 × 32, first choice), UCI Bank Marketing (41 188 × 21) and UCI Online Shoppers Purchasing Intention (12 330 × 18). This report uses the first.

    1. Initial inspection

    A — Data dictionary

    Source. Antonio, Almeida & Nunes, Hotel booking demand datasets, Data in Brief 22 (2019) 41–49 (doi:10.1016/j.dib.2018.11.126); public copy on Kaggle and in TidyTuesday 2020-02-11, from which the CSV in data/hotel_bookings.csv was downloaded. The data come from the property-management systems of two hotels in Portugal: a resort in the Algarve (Resort Hotel) and a hotel in Lisbon (City Hotel).

    What a row is. One booking, with arrival date between 2015-07-01 and 2017-08-31 — 119 390 rows × 32 columns (target + 31 features: 16 numerical, 15 categorical, counting the binary flag and the two IDs agent/company as categorical). Customer identity is anonymised; there is no booking ID.

    Missing values (raw file, 119 390 rows):

    In the source, agent and company are the string NULL when the booking was made without a travel agency / company: their "missing" values are information, not errors. company is 94.31% missing.

    Duplicates. 31 994 rows (26.80%) are exact copies of an earlier row. Without a booking ID they cannot be told apart from the original, and if kept, the same row would land in train and in test. They are not random: 63.1% of the removed copies are cancellations (vs 37.0% in the file) and 42.4% have deposit_type = Non Refund — they are mostly blocks of identical non-refundable bookings made by agencies for groups (in the raw file, 63% of the Non Refund bookings are in the Groups segment, 34% Offline TA/TO, 86% made through an agency; Non Refund drops from 14 587 rows to 1 038 after de-duplication). Decision: drop exact duplicates (keep the first), and report the consequence: the cancellation rate falls from 37.0% to 27.5% (Figure 1).

    No column is constant.

    Columns that leak the target. A feature leaks if its value is only known after the outcome:

    Column Evidence Decision
    reservation_status Canceled (43 017) and No-Show (1 207) ⇔ is_canceled = 1; Check-Out (75 166) ⇔ 0 — it is the target drop
    reservation_status_date earlier than the arrival date in 42 137 rows, 100% of them canceled (2.7% otherwise) — it is the cancellation date drop
    assigned_room_type the room is assigned at check-in: when it differs from the booked one (14 917 rows) only 5.4% were canceled vs 41.6% when equal — a canceled booking never gets a different room drop
    required_car_parking_spaces 0 of 7 416 bookings with a parking space were canceled (39.5% otherwise). An exact 0% is not behaviour, it is a field filled at arrival — found while reading the UMAP islands (section 4.B) drop
    booking_changes counted "until check-in or cancellation", so partly post-booking — but not deterministic (15.5% canceled when > 0) keep, flagged as a risk (section 5)

    Also dropped: company (94% missing, replaced by the flag has_company), arrival_date_year (only 3 values; a deployed model sees only future years) and arrival_date_week_number (redundant with the month, ρ = 0.995 — section 3.A). The IDs agent / company are categories, never numbers.

    C — Target

    After cleaning: 63 221 not canceled (72.5%) and 24 009 canceled (27.5%), a ratio of 2.6 : 1 — moderate imbalance. A model that always says "not canceled" is already 72.5% accurate, so accuracy alone is a poor metric; the next deliverable should report F1 / PR-AUC of the canceled class and use class weights or a tuned threshold. Conclusion: cancellations are the minority class, and the de-duplication changed the base rate, so numbers here are not comparable to studies using the raw file.

    D — Train / test split

    def load_raw(path=DATA_PATH):
    """The CSV as published (agent/company 'NULL' strings are read as NaN)."""
    return pd.read_csv(path)


def clean(df):
    """Row-level rules that need no statistic from the data (safe to apply before the split).

    1. exact duplicate rows are dropped (no booking ID exists to tell them apart; kept, the
       same row would land in train and in test);
    2. bookings with 0 guests (adults + children + babies = 0) are invalid records;
    3. has_company = 1 if a company paid / booked (company is 94% missing).
    """
    df = df.drop_duplicates().copy()
    guests = df["adults"] + df["children"].fillna(0) + df["babies"]
    df = df[guests > 0].copy()
    df["has_company"] = df["company"].notna().astype(int)
    df["agent"] = df["agent"].astype("Int64").astype(str).replace("<NA>", np.nan)
    return df.reset_index(drop=True)


def split(df, test_size=0.2):
    """Stratified 80/20 split with a fixed seed. Returns X_train, X_test, y_train, y_test."""
    X, y = df.drop(columns=[TARGET]), df[TARGET]
    return train_test_split(X, y, test_size=test_size, stratify=y, random_state=SEED)


def load_clean_split():
    """Raw CSV -> clean rows -> stratified split -> model features only."""
    X_train, X_test, y_train, y_test = split(clean(load_raw()))
    return X_train[FEATURES], X_test[FEATURES], y_train, y_test

    • Split 80 / 20, stratified by the target, random_state = 42: 69 784 train / 17 446 test, 27.52% canceled in both.
    • Why stratified and not temporal: the cancellation rate is stable over the years (37.0%, 35.9%, 38.7% for 2015, 2016, 2017 in the raw file), but it is strongly seasonal (14% to 34% by month and hotel, Figure 9). The data cover only 26 months, so a temporal split (last 20% of arrivals ≈ May–August 2017) would test on summer only, mixing "can the model predict cancellations" with "does it transfer to another season". The year is dropped from the features so the model cannot lean on it.
    • From here on, every statistic is computed on the training set only — the test set is not looked at again until the pipeline is applied to it in 4.C.

    2. Univariate analysis

    A — Numerical

    Reading Figure 2 / Table 3, three shapes appear:

    • Right-skewed continuous: lead_time (median 49, mean 80, max 737 days, skew 1.43) — mode near 0 (last-minute bookings) and a long tail of bookings made a year or more ahead. adr is bell-shaped around a median of 98.6 € (Q1 72.3, Q3 134.1), but with one 5 400 € value and one negative price (−6.38): its skewness of 13.1 comes from one row.
    • Zero-inflated counts: children, babies, previous_cancellations, previous_bookings_not_canceled, booking_changes, days_in_waiting_list, required_car_parking_spaces are 0 in 82% to 99% of the bookings, with rare and far non-zeros (up to 26 previous cancellations, 72 previous bookings, 391 days in the waiting list). Their mean and median disagree (median 0) and the skewness is 3.5 to 34.
    • Bounded / near-uniform: arrival_date_day_of_month (uniform, skew 0.00), arrival_date_week_number (summer peak around weeks 27–35), adults (2 in most bookings, but up to 50: a few group bookings), stays_in_weekend_nights (modes 0, 1, 2).

    Conclusion of Figure 3: clipping alone fixes the features whose skewness came from a handful of rows (adr 13.1 → 0.84, adults 16.1 → −0.34), while for long-tailed counts the log1p is what helps (lead_time 1.38 → −0.72, stays_in_week_nights 1.98 → −0.16). For zero-inflated features nothing makes them symmetric (babies 9.6 → 9.6): the mass at 0 is the shape. Table 4 (section 4.A) turns this into the rule used by the pipeline.

    B — Categorical

    Conclusion of Figure 4: every low-cardinality feature is dominated by one value — deposit_type No Deposit 98.7%, distribution_channel TA/TO 79.1%, meal BB 77.9%, customer_type Transient 82.4%, reserved_room_type A 64.6%, market_segment Online TA 59.1%. Rare categories: market_segment = Undefined (1 booking), distribution_channel = Undefined (3), reserved_room_type = L (3) — too few to learn anything from; deposit_type = Refundable (82) and customer_type = Group (449) are small but above the threshold. Arrivals are seasonal: August 12.9%, January 5.4%.

    Conclusion of Figure 5: country (169 values) and agent (315 values) are high-cardinality with a long tail: the top 5 countries hold 68.3% of the rows (Portugal alone 31.3%) and the top 5 agents 68.1% (agent 9 alone 33.0%), while 123 countries and 236 agents have fewer than 50 bookings and together cover only 1.8% and 3.3% of the rows. Keeping the 46 countries / 79 agents with ≥ 50 bookings covers 98.2% / 96.2% of the non-missing rows — this is the min_frequency = 50 used in 4.A.

    3. Bivariate and multivariate analysis

    A — Numerical × numerical

    Spearman, not Pearson. Most numerical features are skewed, zero-inflated or ordinal counts (Table 3), and a single extreme value (adr = 5 400, adults = 50) can dominate a Pearson coefficient. Spearman uses ranks, so it measures any monotone relation and is robust to those tails. The difference is visible: previous_bookings_not_canceled × is_repeated_guest has Pearson 0.443 but Spearman 0.805 (Table 6). For this analysis the month is also converted to its number (1–12).

    Conclusion of Figure 6: almost every pair is weakly correlated (|ρ| < 0.35), so the features carry mostly distinct information. The exceptions: arrival_date_week_number × month (ρ = 0.995, the same information twice → redundant, week number dropped); previous_bookings_not_canceled × is_repeated_guest (ρ = 0.805, strongly related but one is a count and the other a flag → both kept); and arrival_date_year × week/month (ρ ≈ −0.5), an artefact of the coverage (2015 starts in July, 2017 ends in August) — one more reason to drop the year.

    Conclusion of Figure 7: (left) week number is a deterministic function of the month — redundant; (middle) non-repeated guests have almost always 0 previous bookings, and repeated guests are almost never canceled (few red points at is_repeated_guest = 1); (right) longer stays are booked further ahead (ρ = 0.418), and canceled bookings are spread over the whole range, concentrated at larger lead times — neither feature separates the classes on its own.

    Simpson's paradox check. A correlation over the pooled data can hide, or even reverse, the relation inside each group. The two hotels are very different businesses (Figures 9–11), so the same Spearman coefficients were recomputed inside each hotel:

    No pair with |ρ| > 0.1 changes sign between the hotels, so no conclusion above is reversed, and the redundancy of week number × month holds in both (0.995). But some pooled values are an average of two different behaviours: weekend × week nights is 0.326 overall, 0.081 in the City Hotel and 0.604 in the Resort; lead time × week nights is 0.290 vs 0.587. In the Resort, long holiday stays cover both weekdays and weekends and are booked early; in the City Hotel, short stays are either weekday or weekend. Conclusion: the relations between the stay features depend on the hotel — one more reason to keep hotel as an input next to them, so the network can learn hotel-specific patterns.

    B — Categorical × target

    Conclusion of Figure 8: deposit_type is the strongest single categorical signal — 95.0% of Non Refund bookings are canceled (814 bookings) against 26.7% for No Deposit. It is counter-intuitive (paying in advance should prevent cancellations) and is the group-agency pattern seen in the duplicates. Next, the booking channel: Online TA 35.3% vs Direct 14.9% and Corporate 12.5%; TA/TO channel 31.0% vs Direct 14.9%; Transient customers 30.1% vs Group 9.1%; City Hotel 30.1% vs Resort 23.5%. meal matters little (BB 26.6%, HB 26.8%) except SC (35.6%). The 100% bars are single bookings (Undefined, n = 1 and n = 3) — noise, merged into "infrequent" by the pipeline.

    Conclusion of Figure 9: domestic bookings cancel much more — Portugal 35.8% (21 823 bookings) vs 19% for the UK, France and Germany — so country is informative and worth encoding despite its cardinality. The month effect depends on the hotel: the Resort goes from 13.9% in January to 32.8% in August, while the City Hotel stays between 25.2% and 34.4% all year. Hotel and month interact, so both must be given to the network.

    C — Numerical × categorical

    Conclusion of Figure 10 (left): the groups differ in both location and spread. Across segments, the median lead time goes from 3 days (Aviation) to 98–155 days (Groups). Within every segment, canceled bookings were made earlier and are more spread out: Online TA median 41 → 80 days (IQR 95 → 119), Direct 11 → 41 (IQR 66 → 99), Groups 98 → 155 (IQR 185 → 216); overall 38 vs 80 days. Long lead time is a cancellation signal that holds inside each segment, not a segment effect. (right): price grows with the room type in both hotels (location), but the Resort's prices are much more spread for the same room (room A: City median 95.7 €, IQR 39.2; Resort median 60.0 €, IQR 60.2) — the spread is explained by Figure 11.

    Conclusion of Figure 11: the Resort's price is seasonal in location and spread — median 45.8 € in January vs 189.0 € in August, IQR 20.0 → 82.8 — while the City Hotel's median only moves between 81.6 € and 126.0 €, with similar spread all year. adr therefore means different things in each hotel and month (a 150 € night is cheap for the Resort in August and expensive in January), another hotel × month interaction for the network.

    4. Preprocessing

    A — Strategies

    Each choice points to the finding that motivates it; every statistic (median, quantile, mean, standard deviation, list of categories) is learned with fit on the training set only.

    Missing values (training set: children 3, country 364, agent 9 733 rows; Table 2).

    • children → median (0): 3 rows (< 0.01%), and 90% of the bookings have 0 children (Table 3).
    • country and agent → constant category "missing": for agent, missing means "booked without a travel agency" (14% of the rows, Table 5), which is information; for country (0.5%) it keeps the row without inventing a country.
    • company → dropped and replaced by the flag has_company (94.3% missing, section 1.B).

    Outliers — clip each numerical feature to [0, 99.9th percentile of the training set] (UpperClipper), then log1p where the rule below says so. Motivated by Table 3: the maxima are far from the bulk (adr 5 400 € vs Q3 134 €, adults 50 vs Q3 2, days_in_waiting_list 391 vs 99% zeros), and one negative adr. Clipping instead of dropping rows, because a deployed model must also score unusual bookings, and because without it the 5 400 € booking would sit about 95 standard deviations from the mean after scaling — a single input able to saturate the network's activations. Rows affected: 599 training bookings (0.86%) have at least one clipped value.

    # Skewness on train: raw, after clipping at the q99.9 (UpperClipper), and after clip + log1p
num_model = P.NUM_LOG + P.NUM_LIN
upper = train[num_model].quantile(P.CLIP_Q)
clipped = train[num_model].clip(lower=0, upper=upper, axis=1)
skew = pd.DataFrame({"raw": train[num_model].skew(), "clipped": clipped.skew(),
                     "clipped + log1p": np.log1p(clipped).skew()})
rule = (skew["clipped"] > 1) & (skew["clipped + log1p"].abs() < skew["clipped"].abs())
assert set(skew.index[rule]) == set(P.NUM_LOG), "NUM_LOG in pipeline.py must follow the rule"
rows_clipped = int((train[num_model].gt(upper, axis=1) | train[num_model].lt(0)).any(axis=1).sum())

    Categorical encoding — one-hot (OneHotEncoder), because no categorical feature has a usable order for a network (room codes are anonymised; months are cyclic, and a 1–12 number would put December far from January). Two findings shape the encoder:

    • high cardinality and rare categories (Figure 5, Table 5) → min_frequency = 50: categories with fewer than 50 training bookings are merged into one infrequent column per feature. country becomes 48 columns instead of 170 and agent 81 instead of 316, keeping 98.2% / 96.2% of their rows in their own column;
    • a category that appears only in the test set → handle_unknown = "infrequent_if_exist" sends it to that same infrequent column instead of failing. This happens: 9 test rows have a country and 19 test rows an agent never seen in training (e.g. countries ASM, BDI, CYM).

    Scaling — StandardScaler on the numerical features (after clip/log), because their ranges go from 0–4 (total_of_special_requests) and 0–3 (adults, clipped) to 0–484 (lead_time, clipped) and 0–337 € (adr, clipped) (Table 3/Table 4). For a network trained by gradient descent, inputs on such different scales give some weights gradients orders of magnitude larger than others; standardised inputs (mean 0, std 1) also keep tanh/sigmoid units out of saturation. The 0/1 flags and one-hot columns are left as they are (already in [0, 1]). After the fit, the largest |mean| of a scaled column is 0.000 on train and 0.013 on test — the test set is transformed with the training statistics, as it should.

    B — Dimensionality reduction

    All projections use the 192 preprocessed training columns (output of 4.C), coloured by the target. PCA is fitted on the whole training set; t-SNE and UMAP, which are slow and quadratic in memory, on a stratified sample of 5 000 training bookings (27.5% canceled, as the full set).

    PCA. PC1 explains 12.9% and PC2 8.2% — 21.2% together; 16 components are needed for 80% and 40 for 95% of the variance. The variance is spread over many directions: the 192 columns are mostly independent one-hot indicators. Reading the loadings:

    • PC1 — "size of the booking" vs "loyal customer": positive on lead_time (0.41), adults (0.39), stays_in_week_nights (0.36), adr (0.35) and stays_in_weekend_nights (0.30); negative on previous_bookings_not_canceled (−0.35) and previous_cancellations (−0.21). High PC1 = a first-time customer booking a long, expensive stay for more people, well in advance.
    • PC2 — "long cheap stay" vs "short expensive family stay": positive on the two stay lengths (0.43, 0.42) and lead_time (0.33), negative on adr (−0.41), children (−0.28) and total_of_special_requests (−0.21).

    Both components are made of the 13 standardised numerical columns: a one-hot column has variance p(1−p) ≤ 0.25, against 1 for a standardised feature, so PCA on this mixed matrix is dominated by the numerical part. Also, the last 10 of the 192 components have exactly zero variance: inside each of the 10 one-hot blocks the columns sum to 1, so each block adds one exact linear dependency (the "dummy-variable trap"). It is harmless for PCA and for a network with regularisation, but it means the matrix has only 182 independent directions. In the PC1–PC2 plane the classes overlap almost completely.

The islands are the rare non-zero values of zero-inflated features: after log1p + standardisation, a single non-zero value puts a booking several standard deviations away from the 95–99% of zeros, so it forms its own neighbourhood.     Evaluating the maps, and a control. A map can look clustered without saying anything about the data, so each map is measured on two separate questions, and the same procedure is run on a control: the sample with every column shuffled independently (each feature keeps its distribution, but the relations between features and with the target are destroyed).

    from sklearn.cluster import DBSCAN  # noqa: E402
from sklearn.manifold import trustworthiness  # noqa: E402
from sklearn.metrics import silhouette_score  # noqa: E402
from sklearn.model_selection import cross_val_score  # noqa: E402
from sklearn.neighbors import KNeighborsClassifier  # noqa: E402


def evaluate_map(X_high, Z):
    """Two separate questions about a 2-D map Z of X_high:
    - is the neighbourhood preserved?  trustworthiness at k = 5 (local) and k = 30 (wider), in [0, 1]
    - is the TARGET separated?         silhouette with the target labels, and 15-NN accuracy (5-fold CV)
    plus the number of groups DBSCAN finds on the standardised map (how 'clustered' it looks)."""
    Zs = (Z - Z.mean(0)) / Z.std(0)
    return {"trust_k5": r(trustworthiness(X_high, Z, n_neighbors=5)),
            "trust_k30": r(trustworthiness(X_high, Z, n_neighbors=30)),
            "silhouette_target": r(silhouette_score(Z, ys)),
            "knn15_acc": r(cross_val_score(KNeighborsClassifier(15), Z, ys, cv=5).mean()),
            "dbscan_groups": int(len(set(DBSCAN(eps=0.15, min_samples=20).fit_predict(Zs)) - {-1}))}

    Comparison of the three methods.

    • Limits: the sizes of the islands and the distances between them have no direct meaning in t-SNE or UMAP, so the reading above only uses which points are together. And t-SNE cannot place new data: it has no transform (has_transform = PCA True, UMAP True, t-SNE False), so it can only be used to explore the training set, never inside a model or to project the test set. PCA and UMAP learn a mapping that can be applied to new bookings. No 2-D map separates the classes: the decision needs many features at once, which is the job of the network.

    C — Pipeline

    class UpperClipper(BaseEstimator, TransformerMixin):
    """Clip each column to [lower, q-quantile of the TRAINING data]."""

    def __init__(self, q=CLIP_Q, lower=0.0):
        self.q, self.lower = q, lower

    def fit(self, X, y=None):
        self.upper_ = np.nanquantile(np.asarray(X, dtype=float), self.q, axis=0)
        return self

    def transform(self, X):
        return np.clip(np.asarray(X, dtype=float), self.lower, self.upper_)

    def get_feature_names_out(self, input_features=None):
        return np.asarray(input_features, dtype=object)


def build_preprocessor():
    """ColumnTransformer that turns the raw features into a dense, NaN-free, scaled matrix."""
    num_log = Pipeline([
        ("impute", SimpleImputer(strategy="median")),          # children: 4 NaN
        ("clip", UpperClipper()),                               # extreme tails (q 0.999)
        ("log", FunctionTransformer(np.log1p, feature_names_out="one-to-one")),
        ("scale", StandardScaler()),
    ])
    num_lin = Pipeline([
        ("impute", SimpleImputer(strategy="median")),
        ("clip", UpperClipper()),                               # adr < 0 -> 0, adults up to 50
        ("scale", StandardScaler()),
    ])
    cat = Pipeline([
        ("impute", SimpleImputer(strategy="constant", fill_value="missing")),  # country, agent
        ("onehot", OneHotEncoder(handle_unknown="infrequent_if_exist",
                                 min_frequency=MIN_FREQ, sparse_output=False)),
    ])
    return ColumnTransformer([
        ("num_log", num_log, NUM_LOG),
        ("num_lin", num_lin, NUM_LIN),
        ("bin", "passthrough", BINARY),
        ("cat", cat, CATEGORICAL),
    ], verbose_feature_names_out=True)

    5. Synthesis

    Main findings (for whoever builds the model):

    1. Four columns leak the target and are removed: reservation_status, reservation_status_date, assigned_room_type, required_car_parking_spaces (section 1.B; 100%, 100%, 5.4% vs 41.6% and 0% evidence).
    2. 26.8% of the file are exact duplicates, mostly non-refundable group bookings; removing them takes the cancellation rate from 37.0% to 27.5% (Figure 1).
    3. Strongest single signals: deposit_type = Non Refund (95.0% canceled), previous_cancellations > 0 (66.1% canceled, 1 367 training bookings), long lead_time (median 80 vs 38 days, Figure 10), the channel (Online TA 35.3% vs Direct 14.9%) and the country (Portugal 35.8% vs ~19%) (Figures 8–9).
    4. Hotel × month interactions in both the cancellation rate and the price (Figures 9 and 11).
    5. Feature shapes: zero-inflated counts and two long-tail categorical features (Figures 2, 3, 5), handled by clipping + log1p + standardisation and one-hot with an infrequent bucket.
    6. No 2-D view separates the classes (Figures 12–15, Table 9): the best 2-D map keeps 76.7% 15-NN accuracy vs 72.5% for the majority class (78.7% on the full 192 columns), and the shuffled control shows that the islands of t-SNE / UMAP come from the shape of the features, not from groups of bookings.
